Weekly Analyst

Drop a CSV in a folder and do nothing else. If something material changed, a stakeholder-ready PDF appears. If not, the agent stays quiet. It runs on a 1B model, on CPU, with no data leaving the machine.

Most AI analyst demos let the model write the numbers, and a fluent report with one wrong figure is worse than none. Here the model never touches a number: code finds the change, runs the queries and draws the charts, a separate recompute checks every figure, and a person approves the send. The small model does what it is good at: choosing the analysis and writing the words around the evidence.

What the agent does each week

  1. Extract only the columns it needs from the new CSV, read-only, with size and format limits.
  2. Validate and detect with deterministic code: schema changes, then a ranked blend of detectors under a weekly alert budget. Nothing material means no model call and no report.
  3. Plan and investigate. The model picks follow-up checks from a fixed menu (named, parameterised queries first, free SQL last) inside a locked-down query engine.
  4. Draft. The model writes words only. Code supplies every number, chart and table.
  5. Check. A separate implementation recomputes every number in the PDF. Any mismatch, unlisted number or unsafe PDF object stops the run.
  6. Approve. The report waits for a person. Approval re-renders the stamped PDF, re-checks it, and only then sends it.

A small weight edit, found without training (the first edit, now superseded by the LoRA)

We changed 16,384 values, about 0.001% of the model, in two MLP layers. The direction came from the agent's own correct and failing plan outputs, the columns were ranked by how much they push along it, and the strength was chosen on separate dev seeds. On 80 held-out tasks plans went from 64/80 to 80/80 with no grammar. A random direction of the same size changed nothing. The Space now runs the round 2 LoRA instead; this edit is still available there with WEEKLY_ANALYST_LORA=0 as a 66 KB patch to the official f16 model. Limits: synthetic tasks, no grammar, one greedy run, and production adds a grammar and retries, so the real gain is probably smaller. Details are in the model card.

A second edit, for drafts (measured, not shipped, superseded by the LoRA)

Drafts scored 0/80 without a grammar because the draft prompt never shows the schema, so the base model invents keys. Adding a direction to a few columns, the method of the first edit, stayed at 0/40 in every setting. A closed-form MEMIT-style update of down_proj in six layers, fitted at the JSON positions where the model's top token is wrong, took drafts from 0/80 to 80/80 on 80 held-out tasks. On fresh seeds that were never used for any choice, the edit plus the first edit scored 80/80 plans and 75/80 drafts (base 62/80 and 0/80; a random edit of the same norm stayed at 62/80 and 0/80). It changes about 2.6% of those matrices' norm, much more than the first edit, and the smallest rank that worked was 8 (about 221,000 values). On new data, one item or renamed metrics it held (40/40 each) and with the re-request line appended it scored 32/40, but with the instruction reworded it scored 0/40: it overfits the wording. An attempt to refit it on the model's own samples (on-policy) damaged the output format and failed. It is not applied to the Space. The draft problem was later solved properly by the round 2 LoRA (lora3), which scored 80/80 drafts and 40/40 on each of six variants, including two held-out reworded instructions, and is what the Space runs now. Details and failed attempts: results/wsp-draft-edit.md.

Run it yourself

The live demo is the Hugging Face Space. A spike or drop scenario takes about 5 minutes on its CPU; a quiet week takes seconds. To run it locally:

git clone https://github.com/GPA-N/weekly-analyst
cd weekly-analyst
pip install -r requirements.txt
python app.py        # the first run downloads the 2 GB f16 model

The default is the round 2 LoRA file from the model repo. Set WEEKLY_ANALYST_LORA=0 for the older 16,384-value plan patch, or WEEKLY_ANALYST_EDIT=0 for the unedited model. For CUDA use requirements.cuda.txt (supported in code, not shown to use the GPU on the Space).
